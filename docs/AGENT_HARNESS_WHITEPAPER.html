1. Executive Summary

本白皮书描述一套多模型协同 Agent Harness 架构，目标是在 Terminal-Bench 2.1、SWE-bench 等 coding agent 基准测试中， 用 Qwen3.6-35B-A3B（3B active MoE）+ Gemma4 的组合，超越 Ornith 1.5-35B-A3B。

核心策略： Ornith 1.5 的优势来自训练时的自我改进循环（GRPO）。我们通过推理时的多层自我改进（Prime Agent /refine + DSH 插件化 + 多模型协作 + CGC 运行时优化）来弥补甚至超越训练时的差距。
维度 Ornith 1.5-35B 我们的组合 优势来源
Agent 框架 标准 harness DSH 插件化 + Prime Agent RLM 推理时可调
Tool Calling GRPO 训练优化 DSH 结构化 prompt + /refine 迭代 跨会话学习
多模型协作 ❌ 单模型 Qwen3.6 写代码 + Gemma4 推理验证 独有优势
运行时优化 ❌ 无 expert-cache + L4 skip load + MTP CGC fork
端云协同 ❌ 无 DOPD PD 分离 + 跨设备路由 独有优势

2.2 Ornith 1.5 的优势来源

关键洞察： Ornith 1.5 不是新架构，而是基于 Qwen3.5 + Gemma4 微调，通过自我改进训练循环获得优势。 它联合优化三个维度：(1) 任务生成 (2) scaffold 构造 (3) rollout 优化，使用 GRPO 强化学习。 这意味着模型权重本身已经编码了更好的 agent 策略。

Ornith 1.5 的自我改进循环：

┌─────────────────┐ ┌──────────────────┐ ┌─────────────────┐ │ Task Generation │ ──→ │ Scaffold │ ──→ │ Rollout │ │ (生成训练任务) │ │ Construction │ │ Optimization │ │ │ │ (构造解题框架) │ │ (优化解题路径) │ └────────┬────────┘ └──────────────────┘ └────────┬────────┘ │ │ └────────────── GRPO 强化学习 ←──────────────────┘ (联合优化三维度)

4.1 DeepSeek Harness (DSH)

属性值

DSH 四种运行模式对比

模式 工具集 对模型要求 适合场景
Standard file edit, shell, web search, skills, planning, subagents, workflows 高 完整 coding agent
PTC (Code) Standard 全部 + Code Mode SDK 编排 最高 模型生成代码编排工具调用
Minimal bash + str_replace_editor (仅两个) 低 基准测试、小模型
Creator Standard + runtime inspection + plugin experiments 高 自定义 agent preset

DSH 对 Qwen3.6-35B 的提升路径

  1. Minimal mode baseline： 结构化 bash + str_replace，减少无效命令，预估 Terminal-Bench +3~5 pts
  2. Standard mode： 完整 tool 套件 + planning + subagent，预估 +5~10 pts
  3. PTC mode： 模型生成 TypeScript 代码编排工具调用，对 MoE 特别有利（一次性推理利用 35B 总参数），预估 +8~15 pts
  4. 子代理路由： DSH v0.1.2 支持子代理模型选择，可将不同任务路由到 Qwen3.6 / Gemma4

4.2 Prime Agent (RLM + Continual Harness)

属性值
来源Prime Intellect (2026-08-05)
核心抽象Recursive Language Model (RLM) + Continual Harness
ARC-AGI-3 最佳95.5% (Opus 5)
关键特性/refine 自改进、persistent subagents、A2A messaging

Prime Agent 的 Continual Harness

Continual Harness 将 harness 状态形式化为 H=(ρ, G, K, M)：

组件含义CRUD 操作
ρ (Prompt)System prompt 注解create_prompt_note()
G (Sub-agents)子代理规范create_subagent()
K (Skills)工具技能create_skill()
M (Memory)经验记忆create_memory()

/refine 自改进机制

/refine 执行流程: │ ├─ Phase 1: Planning (后台, 不阻塞) │ └─ LLM 分析 trajectory → 提出最小 CRUD 编辑 │ └─ Phase 2: Apply (快速, 仅在 turn boundary) └─ 写入 disk → 重建 system prompt 每条 refinement 记录: - trigger: 触发原因 (失败观察 / 可复用策略) - outcome: 产生的效果 → 改进有证据支撑, 不是任意修改
与 Ornith 1.5 的对比： Ornith 在训练时通过 GRPO 做自我改进，模型权重永久编码了改进结果。 Prime Agent 在推理时通过 /refine 做自我改进，harness 层跨会话持久化（JSONL on disk）。 两者本质相同，时机不同。我们的优势：可逆（rollback）、可审计（trajectory view）、跨会话。

7. 四步 Benchmark 验证计划

Step 1: DSH Minimal Mode Baseline

Step 1 DSH Minimal mode + Qwen3.6-35B

目标： 确认 DSH harness 层对 Qwen3.6 的提升幅度

配置：

  • DSH Minimal mode (bash + str_replace_editor only)
  • Qwen3.6-35B-A3B via llama-server (expert-cache ON)
  • 10 个 Terminal-Bench 任务 (混合难度)

预期： Terminal-Bench 49.2 → 52~57 (+3~5 pts)

对照组： local_rehearsal.py + Qwen3.6 (现有 baseline)

耗时： ~2 小时

Step 2: 加入 Prime Agent /refine

Step 2 + Prime Agent /refine 自改进

目标： 验证 /refine 跨会话学习对 Qwen3.6 的提升

配置：

  • DSH Standard mode + Prime Agent RLM
  • /refine enabled (每轮结束后自动 refine)
  • 同一 10 个 Terminal-Bench 任务, 跑 3 轮

预期： Terminal-Bench 52~57 → 58~65 (+5~8 pts)

关键指标：

  • harness_state.json 条目变化数量
  • 每轮成功率提升曲线
  • refine 产生的 skill/memory 质量

耗时： ~6 小时 (3 轮 × 10 任务)

Step 3: 加入 Gemma4 子代理

Step 3 + Gemma4 推理验证子代理

目标： 验证多模型协作对 agent 准确率的提升

配置：

  • DSH Standard mode + Prime Agent RLM
  • Qwen3.6-35B: 代码生成 + tool calling
  • Gemma4-26B: 代码审查 + 逻辑验证 (subagent)
  • Prime Agent A2A messaging 协调两个模型

预期： Terminal-Bench 58~65 → 62~68 (+2~3 pts)

关键验证：

  • Gemma4 审查是否能捕获 Qwen3.6 的代码错误
  • 多模型协调开销是否抵消准确率提升
  • 子代理 spawn 延迟 (模型加载时间)

耗时： ~8 小时 (含模型切换调试)

Step 4: 全组件联调

Step 4 全组件联调 + 端云协同

目标： 端到端验证, 对比 Ornith 1.5-35B-A3B

配置：

  • DSH Standard mode + Prime Agent RLM + /refine
  • Qwen3.6-35B: Mac M4 (expert-cache + L4 skip) → 27t/s
  • Gemma4-26B: Mac M4 (推理验证子代理)
  • CGC PD 分离: Windows 8GB → Mac M4 decode
  • full 76 Terminal-Bench 任务

目标分数： Terminal-Bench ≥ 67.8 (超越 Ornith 1.5)

耗时： ~12 小时 (76 任务 × 多轮)
