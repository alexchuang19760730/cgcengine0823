3. 八阶段实施计划（整合版）

关键变化： 原 6 阶段计划中，Phase 5 (Exo + iroh-net P2P) 和 Phase 6 (PD 分离联调) 已完成。现在整合 Agent Harness 六阶段，形成完整的 8 阶段计划。

Phase 1: 4D 感知层 (Week 1-2) P0

目标：让 Router 看到系统状态

扩展 FeatureSchema，加入实时系统指标。每个 edge_server 上报 DeviceProfile。

  • 实现 PerceptionLayer 类（D1-D4 四维特征）
  • 每次路由决策附带完整特征向量
  • 特征采集延迟 < 1ms

Phase 2: 智能路由 (Week 3-4) P0

目标：Router 根据系统状态做路由决策

路由决策从"选专家"扩展为"选模式+专家+策略"。输出 RoutePolicyV2。

  • 实现 SmartRouter 类
  • 内存不足时自动切换端云模式
  • 网络延迟高时自动切换纯端模式
  • Accept rate 低时自动关闭 speculation

Phase 3: KV Translation 生产化 (Week 5-6) P1

目标：从合成数据升级为真实模型校准

  • Mac 上跑 500 条校准序列
  • 拟合真实 W_ridge 映射矩阵
  • 集成到 llama-expert-cache.cpp
  • 真实模型 cosine > 0.95

Phase 4: Speculation ROI 门控 (Week 7-8) P1

目标：让 speculation "earn its keep"

  • 跟踪 accept rate、draft cost、verify cost
  • 计算 ROI = (verify_cost - draft_cost) / draft_cost
  • ROI < 0 时自动关闭 speculation
  • 所有决策写入 JSON 报告

Phase 5: Agent Harness SFT 训练 (Week 9-10) P1

目标：用 Freebuff 数据微调 Qwen3.6 + Ornith-1.5

  • 202 条 SFT 轨迹 → Qwen3.6 (general/devops) + Ornith (code/debugging)
  • Mac 上跑 finetune 脚本
  • 目标：单模型质量提升 10-20%

4. 与 Hermes/4D/10-Step 对比

❌ Hermes Router

  • Query-level 路由
  • 静态 FeatureSchema
  • SFT on rules
  • 无 KV 管理
  • 固定 speculation 策略

✅ FusionRoute v2

  • Token-level 路由
  • 动态 FeatureSchema + hidden state
  • CDPO on real metrics
  • KV Translation O(n) 映射
  • 动态 ROI 门控

❌ 4D Perception Matrix

  • LLM 参与决策
  • 需要额外 LLM 推理延迟
  • LLM 输出不确定
  • 高成本

✅ FusionRoute v2 PerceptionLayer

  • 确定性特征收集
  • 零延迟 <1ms
  • 可验证输出
  • 零额外成本

❌ 10-Step Pipeline

  • 10 步串行
  • 静态规则调度
  • 手动 fallback
  • 加节点需改配置

✅ FusionRoute v2

  • 4 步并行
  • 动态 Router
  • 自动 ROI 门控
  • P2P 自动发现 (已完成)
