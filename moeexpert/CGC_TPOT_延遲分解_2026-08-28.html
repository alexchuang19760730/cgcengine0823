② 退化根因：二分定位（isoA/isoB/bypass 三重隔離）

Architecture A（2413fd82b → b55996ad8 → 94e39b695）為支持長 prompt 移除 n_batch cap，代價是 prefill 完全繞過 expert-cache pool path——pool 只分配 slot 不做 pread，FFN 讀到零數據，hidden state 逐層腐蝕。

根因鏈：移除 n_batch cap → 大批 prefill ubatch 走「full-weight 無 remap」路徑 → record_routes 後直接 return → pool 的 ensure_batch 從未被觸發 → slot table 有索引但 pool region 無數據（pool_word=0x00000000）→ 疊加 Architecture A 的「pool 未 adopt 時 remap 寫 slot 索引但 FFN 仍指 full tensor」→ mul_mat_id 讀錯 expert → NaN 級聯 / 0000 輸出。

③ 修復設計：chunked prefill（38 行，單點修改）

設計理念：L4 pool path 的「小批量條件」不是 bug 而是 staging 正確性前提——只有 n_tokens ≤ n_batch 的 ubatch 才走 pool/gather 路徑並觸發 pread 填充。正確支持長 prompt 的方式不是放寬條件（Architecture A 的錯誤方向），而是把長 prompt 切成 n_batch 大小的 chunk，讓每個 chunk 都走 pool path。

// src/llama.cpp/examples/speculative-simple/speculative-simple.cpp（eb16bd129）
// [CGC chunked prefill] decode in n_batch-sized chunks so every ubatch walks the
// L4 expert-cache pool path (small-batch condition) and fills the pool via pread.
const size_t n_enc = inp.size() - 1;
const int32_t n_chunk = llama_n_batch(ctx_tgt);          // = 8（L4 pool 條件）
for (size_t off = 0; off < n_enc; off += (size_t) n_chunk) {
    const size_t len = std::min((size_t) n_chunk, n_enc - off);
    llama_batch batch_enc = llama_batch_init((int32_t) len, 0, 1);
    for (size_t i = 0; i < len; ++i) {
        common_batch_add(batch_enc, inp[off + i], (llama_pos)(off + i), { 0 },
                         off + i + 1 == n_enc);           // 只在最后一格取 logits
    }
    if (llama_decode(ctx_tgt, batch_enc) != 0) { ... return 1; }
    common_speculative_process(spec, batch_enc);         // MTP driver 捕捉 hidden states
    llama_batch_free(batch_enc);
}

為何有效：1222-token prompt = 153 個 chunk，每個 chunk 觸發 41 層 × ensure_batch → 真實 pread（file_reads=36873）填 pool → 後續 decode 命中真實權重。同時 common_speculative_process 按 ubatch 消化（process() 本就逐 batch 處理），MTP draft 的 hidden-state 捕捉不受影響。非 MTP 路徑（ctx_dft 獨立 KV）也改為 chunk 循環保持對稱。
