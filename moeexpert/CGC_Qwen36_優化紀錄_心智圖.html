三、記憶體 / Expert 流式 Pareto

§13.57/13.100/13.103/13.104/13.108 · 16GB Mac 的 pool×slots 定案

s96 + p96 = 支配點

slots96 > slots64（−1~4%）；pool96 覆蓋 64.6% vs pool80 56.4%（+8.2pp）→ 4.375 tok/s。§13.103/13.108

pool112 定案（§13.116/13.117）

r3 家族 7/7 配對 +5.0%；r4 家族 3/4 配對 +1.9%（preload 7.4GB 較大、收益稀釋但方向一致）。預設 96→112 為兩家族共用。§13.116/13.117

--scan-profile 漂移檢查

run_prod_qwen36.sh 一鍵掃 96/112 交錯 + coherence gate。§13.113 兩掃描方向相反（髒窗）；§13.116 乾淨窗重驗 7/7 配對 p112 勝 → 預設翻 112。

embed q4 的 RAM 槓桿是幻覺

ResidentBuffer 是 mmap demand-paging——embed 每步只 gather 4KB，物理佔用 ≈2MB。省的是磁碟不是 RAM。§13.104

top96 mix profile

code+prose 混合 trace 生成（make_mix_hotpool_profile.sh），r3/r4 共用（同 expert IDs）。§13.80.x

PRELOAD=sync 必須

pool96 的 6.4GB async 背景讀會跟 decode miss 搶 SSD；sync 是 §13.103 定案。

四、GPU Kernel 優化（計算/IO 分解）

§13.81/13.82/13.83/13.85/13.87/13.92/13.95/13.98/13.101/13.102 · GPU 176ms / wall 245ms 分解

  • linear_attn 全鏈 4-bit dequant-inline：deltanet_project_q4 kernel（§13.82/13.101）

  • slot8 3-bit dequant 併入 GEMM（§13.87）

❌ 證偽 / 天花板

  • CB 合併 42→6 雙重證偽：層間強資料依賴，跨層合併無收益（§13.64）
  • 全鏈 megakernel 融合 <1%：中間張量全 <100KB/層（§13.95 白皮書）
  • GEMV = 計算 bound：GatedAttn q4 省 410MB 頻寬也只有 +0.4%（§13.92 教訓）
  • 頂層天花板：40 層 × 256 expert × top-8 的計算量物理下限 ≈ 5-5.5 tok/s（§13.95）
wall 245ms 構成：GPU ~153ms（63%）+ fill ~40ms + idle ~40ms + CPU 序列化。剩餘最大可動手項目 = P1：fill 與 encode 的 CPU 並行（wall → ~203ms，約 +14%，估 4.9 tok/s）。

九、llama.cpp fork 線（bounded residency + Metal 併入）

LLAMACPP_EXPERT_BOUNDED_RESIDENCY_FORK_方案.md §7/§8 · 2026-08-15：-ngl 0 轉正、n99c 4GiB 11.08、MTP 放著、預測線 P0 證偽終止

-ngl 0 bounded residency 已轉正（P0 現行可用）

L1 skip-load（loader 跳過 expert 載入）+ L3 Option A（static slot pool）全鏈 bit-identical：1GiB cache 換 ~4.1GiB RSS（mmap 128 tok −52%），RSS 2.67GiB bounded。1GiB cache 4:1 槓桿成立。

Option A 真實文本 = −7%（修正 −1.8% 假象）

llama-bench 喂隨機 token（54% hit、~56K pread），−1.8% 是低負載假象（今日重跑 −17%）。llama-simple 真實文本：base 14.2 tok/s 穩定、Option A 13.2（−7%）；L3-B ≈ Option A（preads ~19K 為主因）。

凍機事件（13:08 重啟）已定位

-ngl 99 + cache + skip-load + mmap：Metal 在 graph-alloc 讀未寫入的 mmap expert 張量 → 9GB 冷頁 fault 風暴 + Metal buffer 分配 → 系統硬掛。診斷一律 -no-mmap；「-ngl 99 + cache + mmap」列為禁區。

copy 時機根因（三臂隔離證實）

-ngl>0 整個 graph 是單一 MTL split：remap/expert 在 split 開頭 copy（hook_swap=0），hook mid-compute 才寫 → Metal 讀 stale/零 ids → 全路由 expert 0 → tabIndex 退化。NOGATHER 隔離：無 remap/swap 時與 base 相同。

MTP 線封存：官方 MTP+IQ3 檔正確權重下仍淨負 6.4×（§8.59）

peculiar-ragdoll/Nail-Qwen3.6-35B-A3B-GGUF-MTP 官方 IQ3_XXS 檔（hf-mirror + aria2c 68MiB/s 下載）：20 顆 blk.40 全在（含缺的 shared_head_norm）、Q2_K/Q3_K experts 進 pool 免 CPU override、無 OOM。accept 0%→14.3%（權重根因修好）但 MTP-4 1.47 vs C0 9.47 t/s——draft ctx 每 token 跑全模型，328 draft 全價抵不過 47 接受。手作重建（p0_mtp_rebuild.py，含 +1 norm / shared_head_norm）被官方檔取代。

A+B split 已修復（封存條件 1 ✅）

三層缺一不可：① loader router 權重 CPU buft ② sched expand-gpu 釘 topk CPU ③ hook resident passthrough（real ids、不 swap/不 fill）。結果每層 [MTL attn]→[CPU router+topk]→[MTL FFN]→[CPU combine]——白皮書 A+B。雙家族（qwen36 IQ2 / gemma4 IQ3_S）-ngl 99 + cache 全 bit-identical。

剩餘：封存條件 2/3

skip-load 仍封 -ngl 0；條件 2/3 = 把 skip-load 併入 -ngl>0（loader 跳過 expert + hook 切回 bounded mode），驗證 gemma4 IQ3_S（11.29GB）壓進 11.45GB Metal working set 不再 OOM。

診斷工具集（全 env-gated 預設 OFF）

LLAMA_EXPERT_CACHE_ALLOW_NGL=1（診斷用放開 gate）、CGC_SCHED_DBG=1（split 結構 + hook_swap 計數 + Metal copy dump）、g_expert_swap_count。詳細見 RUNTIME_CONTROLS.md llama.cpp fork 章節。
