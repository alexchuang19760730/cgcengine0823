§1 開發介紹：代碼 / Shell / GGUF

本 fork 在 llama.cpp 上實作 CGC bounded-residency 專家快取：MoE 專家權重不常駐 GPU，以 4GiB bounded pool + 檔案 pread 按需填充，使 35B MoE（13.2GB）能在 16GB 統一記憶體機器上 -ngl 99 全卸載。所有程式碼位於 src/llama.cpp（生產目錄），build 產物隨 git 版控（checkout 免重建可驗證）。

§3 指標說明

指標定義判讀本輪實測
t/s（吞吐）生成 token 數 ÷ decode 壁鐘時間MTP steady ≥26 為回歸底線；非 MTP ~7 t/s 屬結構性（GPU-bound 專家收集，勿在該路徑追速度）26.573
accept rate投機 verify 接受的 draft token 比例≥99% 為健康（draft 品質 + remap 正確性）99.187%
hit rate專家請求命中 pool 比例（runtime，final stats）≥88%（LAYER_CAPS 40-40:256 生產 profile）88.9%
fast-path cold 率fast path 觸發 ZERO-slot 映射比例~65% 為結構性 churn（per-layer 路由工作集 > 槽位）；LAYER_CAPS 後 draft cold 32%→0%draft 0%
pread_usec填充讀檔累計時間多執行緒累計值（16 workers ≈ 2× 壁鐘）——不得拿壁鐘除它；steady I/O 僅 ~2s/40s—
wait / submit / filldecode 分解：GPU pipeline 等待 / 提交 / catch-up 填充wait 主導 = GPU-bound（2326µs/hook clean）；fill ~1.3%/step 非瓶頸wait 主導
bit-identity同 prompt/seed/greedy 下輸出 byte 級一致fork 硬性要求；任何分歧 = P0PASS

速度量測紀律：A/B 必須同 pair 內比較（首跑冷 page cache 常假性慢 20%）；乾淨測量 = 重開機 → 1 次暖跑 → 只量一次。Q6_K head 載體專家讀取比 headIQ2 多 37%，跨載體比較無效。

4.5 incident：llama-server 測試觸發 macOS 核心 panic（2026-08-30 18:59，已定案）

項內容
症狀整機凍結 91 秒後核心強制重開機（watchdogd 無心跳）；非 app crash，是 kernel panic（panic-full-2026-08-30-185924.0002.panic，panicked task = llama-server，jetsam 出現 484 次）
根因16GB 統一記憶體被行程疊加超賣到核心 wedged：server 測試視窗內 3 次重啟（各重讀 13GB --no-mmap）+ 同視窗 13GB llama-simple 對照 + 4GiB wired Metal pool（不可逐出）+ IDE → 壓縮/jetsam 追不上 → 核心執行緒餓死
判別要點CGC_WATCHDOG=1 是行程內 GPU watchdog，救不了 kernel 層凍結；整機無回應重開機 → 查 /Library/Logs/DiagnosticReports/panic-full-*.panic
鐵律(1) 一次一個重工行程：server 運行期間禁止任何 13GB 級操作（simple 對照/量化/HF 下載）；(2) 重啟 server 前 ps 確認舊行程已死；(3) 避免短時間重啟風暴（每輪 = 13GB page cache）；(4) 附帶損失：/tmp 診斷 log 全滅——重要 log 即時 tee 到 repo 外持久路徑

4.6 修正一則錯誤結論：KV cache 瘦身（-c 1024）不成立

項內容
原說法「-c 2048 → 1024 可替 server 瘦身」（直覺，未驗證）
實測數學從 GGUF 檔頭解析：qwen35moe，GQA head_count_kv = 2（非 16）、k/v_len=256、40 層 → KV = 4 KB/token；-c 1024/2048/4096 = KV 4/8/16 MB——相對 13.2GB 權重 + 4GiB wired pool 是 0.03% 雜訊
定案維持 -c 2048（與生產線一致）；當機根因是行程疊加，不是 n_ctx。教訓：dense 模型 KV 直覺不可移植到 GQA MoE——下記憶體結論前先算 KV 數學（2 × n_head_kv × (k+v) × 2B × n_layer）
