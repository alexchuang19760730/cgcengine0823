四、實作內容：main-path early down coalescing

這次實作刻意不把它包裝成 single-shader fused-down kernel，而是先做一個更穩的 host-side coalesced phase-2：當 fused gate+up+glu 成功後，直接在同一個 encode site 立即 dispatch 對應的 ffn_moe_down，再把該 node 標記 consumed。

範圍本次處理本次不處理
主路徑iq2_s -> iq3_s 立即 dispatch + consumed—
晚層旁支保留 stock fallbackiq4_xs（layer 34/38）
舊分支不回頭碰gate+up-only 重新試驗

Guard 條件：相同 ids tensor、down->src[1] == fused_glu_output、down weight type 精準等於 iq3_s、contiguous F32 dst，以及跨 in-between nodes 的 galloc overlap rejection。這樣做的目的很明確：把正收益吃掉，但不把 correctness 風險放大。

核心策略（簡化描述）
1. gate+up+glu fused dispatch 命中
2. 向後尋找同 ids、同 glu 輸出的 ffn_moe_down
3. 若型別為 iq3_s 且無 overlap 風險，立刻 dispatch down
4. 將該 down node 標記 consumed，避免後續 stock 路徑重複 dispatch

七、後續建議

這輪已經把最值得碰的主路徑吃掉了。下一步如果要繼續追 verify ceiling，我會照這個順序走。

優先級方向理由
1把 late-layer iq4_xs side path 補成同型 cut 或更明確 fallback audit目前只剩 layer 34/38 的旁支沒吃到
2把 gap=4/5 strip 做更進一步 batching / coalescing目前仍是 host-side phase-2，還有壓 dispatch granularity 的空間
3若收益停滯，再評估 single-shader fused-down那會是更高風險但更深的下一刀

不建議：重新回頭做沒有新證據支持的 gate+up-only 試驗。這輪 audit 已經清楚說明那不是目前最有價值的方向。
