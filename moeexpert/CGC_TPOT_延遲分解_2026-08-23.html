② CGC 引擎機制是什麼（為什麼需要它）

Qwen3.6-35B-A3B 是 MoE：每層 256 個 expert × 40 層，全部 resident 遠超 M4 Max 的 11.45GB Metal working set（base 13.2GB → 硬 OOM）。CGC 引擎用 bounded-residency expert cache 讓 decode 只在 GPU 保留「當下工作集的熱 experts」。

核心機制（4 件事）
① L4 Metal zero-copy pool：把 model 的 expert tensor 記憶體直接當 pool（adopt_pool_region），0-copy、不額外吃 GPU；slot 上限由 CGC_EXPERT_CACHE_BYTES 決定（~210 slot/layer）。
② eval callback（pre-hook）：top-k 算完立刻觸發 → ensure_slot + 填真權重 + 更新 remap table，讓下一步的高頻 expert 已在 GPU → ~95% hit。
③ segmented async dispatch（CGC_OA_ASYNC）：Metal splits 非同步提交，免逐層 callback sync。
④ submit-after + semaphore wake（CGC_SUBMIT_AFTER=1）：下一個 segment 等上一個 callback 完成才提交 → 避免 remap race（錯誤輸出）；semaphore 喚醒取代 sched_yield poll（8.35 → 15.6 t/s）。

miss = 結構性 drift：剩餘 ~4-5% miss 是「首次見到的專家」（長 prompt 下 pool 不可能全 resident），hook 的冷讀 pread 是 decode 序列化的主成分。hit rate 94.3%（短測）→ 95.9%（長測）。

參數值機制（做什麼 / 為什麼）
-ngl99full GPU offload。base 13.2GB > 11.45GB → 只有 + cache 換出非熱 experts 才能 full offload（§8.38）。
CGC_EXPERT_CACHE_BYTES4294967296（4GiB）L4 pool 容量上限 → 決定每層 slot 數。4GiB = 本機安全頂（5.1GiB 即 Metal OOM）。限制 resident 數避免無界成長爆 VRAM。
CGC_SUBMIT_AFTER1（強制）正確性。submit-ahead 是 racy（GPU 可能讀到舊 remap → 錯誤輸出）。submit-after = 上個 callback 完成才 submit 下段。
semaphore wake內建Metal completion handler semaphore 喚醒（ggml_metal_wait_cgc_done），取代 sched_yield poll：8.35 → 15.6 t/s。
LLAMA_EXPERT_CACHE_ALLOW_NGL1-ngl>0 時啟用 cache 的硬 guard（n99 必要）。
LLAMA_EXPERT_CACHE_WORKERS8背景 prefetch 執行緒數（pool8 甜蜜點；16 反效果，§8.12）。
LLAMA_EXPERT_CACHE_L4_SKIP_LAYER01blk.0 排除 pool（修復，§8.35/8.36）。
CGC_N_CB8MTL encode 平行化（cb8 飽和點；cb16 反效果 11.78 t/s，§8.93）。
CGC_OA_ASYNC1Metal splits 走 async dispatch，免每層 callback sync（qwen36 +12.6%，§8.77）。
CGC_WAKE_POLL_US15semaphore 之後的 fallback spin 延遲（§8.51；semaphore 為主、poll 只是備援）。
LLAMA_EXPERT_CACHE_PIN_PROFILEoff（預設）calibration 高頻 profile 預 pin。非 coding prompt 反而降速（profile 與 workload 不匹配）→ 預設 off，opt-in。
--no-mmapon凍機防護（mmap 9GB 冷頁風暴根因）。
-t8CPU threads。
